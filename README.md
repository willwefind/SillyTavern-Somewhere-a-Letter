# Somewhere, a Letter · 世界某处的来信 💌

一个轻量级 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 前端扩展。给某个角色写一封信，收到独立回信，在自己的信箱里收藏和保存。

> **v0.3.0 Letter Studio 测试版**。新增指定页数、实时信纸预排版、系统及导入字体、字号与墨色。沿用已实测通过的 iOS 长按保存与原生分享路径；新版排版功能仍需要 PC／iOS 实机验证。

## 安装和更新

新用户：打开 SillyTavern → **扩展 → 安装扩展**，粘贴仓库地址：

~~~text
https://github.com/willwefind/SillyTavern-Somewhere-a-Letter
~~~

已安装用户：打开 **扩展 → 管理扩展（Manage Extensions）**，找到 Somewhere, a Letter → **检查/安装更新**，完成后刷新酒馆网页。单独刷新网页不会自动把 GitHub 的修改拉到本地。

**无需卸载重装，不要清理浏览器站点数据。** 旧信、星标、草稿保存在原来的 IndexedDB / LocalStorage 位置，v0.3.0 不迁移、不清空旧存档。

## v0.3.0 · Letter Studio / 信纸工作台

点击任意回信中的 **「排版／导出 PNG」**，先进入独立的信纸工作台。这里不是重写角色回信，也不会调用 API：所有操作只在本地 Canvas 上进行。

- **自由分页**：自动，或指定 1–6 页。页面均衡分配正文；如果短文没有足够行数，不生成空白页。如果长文装不进目标页数，会在安全范围内**增高纸张**，绝不截断正文。单页过长超出移动端安全高度（4096 px）时，提示增加页数或缩小字号。
- **实时预排版**：修改设置后短暂防抖重新排版，切换上一页／下一页查看。最终 PNG 直接来自这些预览文件，因此字体、分页、颜色不会在导出时二次重排。
- **字体选择**：系统宋体、系统黑体，及在当前设备上检测到的楷体、苹方、思源宋体、Georgia 等候选字体。浏览器无法保证列出设备的**全部**已安装字体；未知候选不会被当作已安装。
- **自行导入字体**：支持 TTF、OTF、WOFF 和 WOFF2（单文件最多 12 MB，最多 12 款）。字体以单独的 IndexedDB \`somewhere-a-letter-fonts\` 保存在当前浏览器，选中时再加载；可以删除。**字体文件不包含在信件 JSON 备份中，不自动跨设备同步**，也不会传给模型 API。
- **字号**：24、26、28、30、32、34、36 px；默认 30 px。
- **墨色**：墨黑、暖棕、深灰、深蓝、暗红和浏览器自定义取色；默认墨黑。
- **排版偏好记忆**：上次选择的页数、字体、字号、墨色保存在本地，下次打开仍可使用；可一键恢复默认。
- **iOS 保存保留并升级**：iPhone/iPad 上预览图片可以继续长按保存到相册，或使用原生系统分享保存本页／分享全部页；PC 点击「下载全部 PNG」仍为 Blob 文件下载。
- **轻量移植**：借鉴同作者 [拾句 Shiju](https://github.com/willwefind/shiju) 的英文整词换行、中文标点避头尾、分页均衡的排版算法，但不复制整个拾句编辑器，不包含大型字体素材和依赖。
- **旧信件不变**：原信、回信、星标、草稿、API 连接与已有 JSON 备份格式完全不变，没有任何数据库迁移。

**测试建议**：PC 打开一封长回信，分别选自动／1／2／6 页，确认页面数与信纸高度、排版无截断；切换字体及墨色，预览后下载 PNG；导入一款本地字体，确认刷新后仍可选，再删除。iOS 测试折叠设置、图片长按保存、系统分享、上一页／下一页，以及切换字号时不会弹出键盘或移动信箱面板。

## v0.2.5 · iOS PNG 保存修复

用户反馈：iOS Safari 点击回信「导出 PNG」后显示下载选项，但不论单页还是双页均未在「文件 → 下载项」中找到图片。PC 可下载，拾句导出正常。

**根因方向**：本扩展原先使用 Canvas 的 `toDataURL()`，然后对带 `download` 属性的临时链接执行模拟点击；iOS Safari 对该链路的下载行为不稳定。拾句实际使用 Canvas `toBlob()` + `URL.createObjectURL()`，并优先调用用户脚本专用的 `GM_download`；普通酒馆扩展无法直接调用该专用接口。

**本版解决方式：**

- 图片均以 Canvas `toBlob('image/png')` 生成真正的 `File` 对象。原排版、分页、文件名和 PNG 格式不变。
- **iPhone/iPad**：点击「导出 PNG」先进入独立的**信纸预览**，不会自动假装下载成功。
  - 点击「分享／保存本页」，直接从用户手势调用 iOS 系统分享菜单，可选「存储到文件」或可用的图片保存目标。
  - 如果回信有多页，额外提供「分享全部 PNG」（设备支持多文件分享时可用）。也可以左右页切换，逐页分享。
  - 如果系统分享不可用，还可以**长按预览图片**，或者点击「打开原图」进入浏览器图片页面后使用系统保存操作。
- **电脑端**：继续点击按钮直接请求下载，但改为 Blob URL；多页之间增加短间隔，避免瞬间连续弹出。
- 状态提示只报告「已请求下载」或「系统分享已关闭」，不会谎称浏览器或操作系统已经成功保存文件。
- 无需任何新依赖、后端权限或数据库迁移；不更改角色、API、收藏、草稿和信件正文。

**建议测试（iOS Safari）**：找一封一页回信，进入预览，点击「分享／保存本页」→ iOS 分享菜单 →「存储到文件」，指定文件夹后去「文件」App 验证；再试两页回信的「分享全部」或逐页保存。如果菜单中没有「存储到文件」，尝试长按预览图／打开原图。PC 端确认仍可直接保存 PNG。

## v0.2.4 · iOS 输入键盘可视区域修复

根据 iPhone 实机反馈：点击角色搜索或写信输入框后，iOS 软键盘出现时酒馆页面被自动向上平移，信箱可能完全离开屏幕；手动拖回页面又会使输入框失去焦点。

- **跟踪 iOS 可视区域**：新增 visualViewport 的高度与 offsetTop/offsetLeft 监听（包括 scroll / resize），并通过实际 DOM 位置测量纠正根元素被浏览器平移后造成的偏移。
- **输入期间动态缩放面板**：聚焦手机端搜索框或正文时，信箱会缩至键盘上方的可见空间，输入区在信箱内部滚动。整个过程不主动取消输入框焦点，也不会滚动酒馆聊天页。
- **防止 iOS 自动放大**：手机上的输入框、文本域、搜索栏和下拉框使用至少 16px 的字号，避免 Safari 在聚焦小字号输入时自动缩放整个页面。
- **紧凑输入布局**：软键盘显示时收起信箱中非必要的导航与头部装饰，把空间优先留给输入和搜索结果。
- **取消自动唤起键盘**：手机端点击「写一封信」不会立刻聚焦主题输入框；由用户主动点击具体字段。
- **不影响桌面端和存档**：PC 端仍采用原居中面板；信件、草稿、收藏、API 预设和 JSON 备份结构没有变化。

**测试建议**：更新后用 iPhone 打开信箱，先点收件人搜索输入几个汉字并选择角色，再在「写一封信」中分别测试主题、署名和正文输入；连续输入时观察信箱是否始终出现在键盘上方，输入框是否保持焦点；最后收起键盘，再打开查看信件是否正常。

## v0.2.3 · 随身册式手机信箱面板

本次修复来自 iOS 实机截图：信封小印可以拖动，但**展开后的整个信箱面板仍被酒馆移动端布局截掉顶部**，无法完整查看和操作。

- **不只是按钮位置**：移动端展开面板改用真实窗口尺寸（必要时结合可视区域高度）计算位置，不再依赖此前的固定全屏布局。
- **参考《何曾梦觉》随身册**：根据酒馆发送栏实际位置，把面板安放在发送栏上方。
- **展开面板也能拖动**：按住手机端标题栏空白处拖动整张信箱；点关闭、主题、设置等按钮不会触发拖动。转屏或窗口变化后重新限制在可见范围内。
- **手机界面紧凑化**：缩小标题与导航间距；浏览档案时收起收件人搜索（可进入「角色信箱」搜索），写信时显示收件人搜索；阅读回信和设置时隐藏侧栏，释放正文空间。
- **内容独立滚动**：长信列表、正文和设置可以在面板里滚动。手机为无暗色遮罩的轻浮窗，点面板外面关闭，同时不挡住下面的酒馆操作。
- **桌面端不变**：PC 保留原居中信箱。旧信件、收藏、草稿、API、备份与 PNG 不迁移、不清空。

**iOS 测试**：打开小印，检查标题及关闭键是否全部可见；按住标题栏拖动；切换所有信件、收藏、角色信箱、写信、设置；长信滚动；点外部关闭；转屏或唤出键盘后检查面板是否可见。

## v0.2.2 · 随身信箱入口

依据《何曾梦觉》角色卡中「随身册」的移动端定位方案调整信箱入口：

- **纯图标小印**：悬浮入口仅显示信封符号，不再显示「信箱」文字，节省手机屏幕空间。按钮带文字说明及无障碍标签。
- **PC / 手机都可以拖动**：按住图标移动，超过 5 像素才算拖动；轻点正常打开信箱，拖动结束不会误触打开。
- **位置自动记忆**：拖动完成后把坐标保存在本浏览器 LocalStorage；下次刷新酒馆仍在原位置。
- **移动端定位修正**：改为 JavaScript 根据 `innerWidth / innerHeight` 设置明确的 `left / top`，不再使用容易受到部分手机酒馆页面 transform 影响的 `right / bottom`；屏幕缩小或转屏时自动保持图标在可见范围内。
- 保留 v0.2.1 原生扩展菜单入口作为备用，不新增依赖，也不触碰旧信件、API 配置、收藏与草稿。

**测试建议**：PC 端拖动信封后刷新，检查位置记忆；手机端分别测试单击、长按拖动、上下左右挪动、转屏后是否仍可点击。悬浮入口在页面最初会出现在右侧、聊天输入区上方，之后以你拖动保存的位置为准。

- **刷新连接列表**：在酒馆「API 连接」中创建或修改 Connection Profile 后，无需刷新整个酒馆，可回信箱设置点击「↻ 刷新连接列表」。

### 为什么 API 下拉框只有默认选项？

信箱独立选 API 依赖酒馆内置 **Connection Profiles（连接配置）**。打开酒馆的 **API 连接**面板，先设置好 API 类型、模型及相关参数，再在 Connection Profiles 部分创建并保存一个带名字的连接配置。之后打开信箱 → ⚙ 设置 → **刷新连接列表**。已保存的、支持 Chat Completion 或 Text Completion 的配置才会出现在列表中。

**仅仅在酒馆填写 API Key、选中模型、连接成功，并不等于已经保存 Connection Profile。** 如果不需要专用连接，保持「跟随酒馆当前 API」即可。信箱不会为你自动新建配置，也不会修改主聊天 API。若你有已保存配置却仍看不到，先确认 Connection Profiles 扩展已启用，并检查信箱给出的错误提示。

## v0.2.0 主要功能

- **所有信件**：以 Gmail 式双栏导航和统一信件列表展示所有角色的往来信。
- **全局星标收藏**：跨角色汇总所有已收藏信件，单击 ☆ / ★ 收藏或取消。原来已经收藏过的信会直接显示。
- **信件搜索**：顶部搜索栏根据角色姓名、主题、原信正文、回信正文、署名进行浏览器本地即时过滤，不调用模型。
- **角色信箱**：在左侧选择收件人后可进入该角色专属归档；选择收件人本身**不会自动跳出**「所有信件」或「星标收藏」。阅读旧信也不会擅自改变写信收件人。
- **独立写信**：点击「写一封信」，自由填写主题、署名与正文；角色原本的人设与主要世界书用于一次性独立回信。
- **设置 → 回信 API**：默认「跟随酒馆当前 API」，也可以选择酒馆 **Connection Manager（连接管理器）** 中已有且受支持的连接预设。独立预设调用不会切换主聊天的 API，不需要重新输入 API Key；如果连接不可用会报错，不会静默切回默认连接。
- **设置 → 主题**：日间 / 夜间模式；顶部 ☾ / ☀ 也可一键切换。只影响信箱自身，不修改酒馆全局主题。
- **设置 → JSON 备份与恢复**：所有角色的信件、收藏状态和草稿导出至 JSON；恢复时不覆盖现有信件和草稿，重复 ID 跳过。
- **草稿**：按角色自动保存，切换角色或刷新浏览器仍可恢复。成功收到并归档回信后清空对应草稿；API 或存档失败则保留。
- **无题摘要与 PNG**：主题为空时用信件正文的首句概述代替无题；导出 PNG 信纸，长信自动分页并显示浏览器本地日期。

## 重要边界

**一封来信 → 一次模型生成 → 一封回信。**

- 不读取当前聊天内容、Persona、过往信件、角色关系或用户长期记忆。
- 只读取本次所选角色的角色卡设定和主世界书；若主世界书未绑定，尝试读取卡内嵌的 `character_book`。
- 不读取额外辅助世界书、全局世界书、聊天专属世界书和 Persona 世界书。
- 世界书激活是轻量匹配（常驻、基础关键词、简单条件、字数预算），**不完全等同**于 SillyTavern 的递归世界书引擎。
- 不做连续通信、好感度、已读未读、标签管理，也不新增后端服务或第三方 JS UI 框架。
- 对角色自身的语言和回信长短不强加模板；模型仍可能受当前后端参数与所选连接预设影响。

### 关于 API 连接切换

- 默认选项沿用原始 `generateRaw()` 生成逻辑，继续使用酒馆当前 API 配置。
- 选择独立连接时走官方 `ConnectionManagerRequestService`，支持其允许的 Chat Completion / Text Completion 连接预设。**需要事先在 SillyTavern 的连接管理器中创建好预设**。
- 独立连接使用预设的模型与 API 凭据，不会保存 Key，也不会修改主聊天所选配置。
- 此功能是可选的。未开启 / 未安装 / 禁用连接管理器时，使用默认 API 仍然正常。

## 隐私与保存

- 信件及星标记录保存在本浏览器对应站点的 **IndexedDB**，草稿和界面偏好保存在 LocalStorage，所有信件搜索也在浏览器本地执行。
- 旧信和收藏不会因为切换角色而丢失；但不同浏览器、不同设备不会自动同步。清理站点数据可能永久删除信箱，请定期备份。
- **同一浏览器和同一站点来源上的不同 SillyTavern 登录用户可能共享这些本地数据**。公用设备请注意隐私。
- 云端 API 调用仍需将本次来信、角色人设及相关主世界书传输给所选模型服务商。
- JSON 文件可能包含私密现实经历，请妥善保管。恢复按信件 ID 判断重复；删除角色卡后，原信仍保存在备份中，但不会自动关联至重新导入的新卡。

## 项目结构

~~~text
manifest.json       扩展清单
index.js            导航、统一信件列表、搜索、阅读、写信、设置
style.css           双栏布局 / 手机适配 / 日夜主题
src/launcher.js     可拖动信封小印与本地位置记忆
src/panel.js        移动端展开面板定位、拖动与重排
src/engine.js       角色和主世界书读取、独立回信构建
src/api.js          当前酒馆 API / Connection Manager 独立预设
src/storage.js      IndexedDB 存档与备份恢复
src/drafts.js       LocalStorage 角色草稿
src/backup.js       JSON 备份文件处理
src/export.js       Canvas 中文标点排版、弹性页数与 PNG 导出
src/studio.js       Letter Studio 预排版面板和 iOS 分享／PC 下载
src/font-manager.js 本地设备字体检测与 IndexedDB 字体管理
~~~

图片排版借鉴 [拾句 Shiju](https://github.com/willwefind/shiju) 的换行与分页算法；仍未引入其完整 UI 或字体素材，以便保持插件轻量。

6. 切换收件人不会自动改变「全部信件」／「星标收藏」视图，也不会把原来的草稿转移给别人。
7. 切换 ☀ / ☾，关闭信箱再打开、刷新网页后，夜间/日间偏好仍保持。
8. 设置里默认 API 仍能生成回信；选择 Connection Manager 预设后由选中的模型响应，同时主聊天 API 不变化。
9. JSON 备份/恢复与 PNG 导出正常，旧信和草稿保持不变。
